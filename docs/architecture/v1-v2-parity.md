# V1/V2 Parity

Source code and tests are authority. This matrix records observed behavior, not desired equivalence.

## Runtime ownership

- **V2 is the canonical runtime.** New runtime capabilities land in `packages/core` and reach hosts
  through the Protocol/Server surface: Protocol API → Server handlers → `SessionV2` → durable
  `SessionInput` → `SessionExecution`/coordinator → Location-scoped runner → one
  `llm.stream(request)`, with Location-scoped tools, permissions, filesystem, MCP, and diagnostics.
- **V1 remains the compatibility runtime.** app/TUI → opencode server (legacy routes) →
  `SessionPrompt` loop → V1 tools, MCP, and LSP. V1 stays functional and is not migrated
  opportunistically; parity work never deletes a V1 path that still has consumers.
- **Bridge.** Both runtimes share one database, `EventV2`, `Config`, `Catalog`, permission storage,
  and session rows. V2 Location services are built by `buildLocationServiceMap`, and hosts inject
  their V1-backed capabilities through that replacement list instead of importing V1 code into Core.

## Generated and frozen artifacts

| artifact                                                            | writer                                    | policy                                                       |
| ------------------------------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------ |
| `packages/sdk/js/src/v2/gen`                                         | `packages/sdk/js/script/build.ts`         | generated; regenerate, never hand-edit                        |
| `packages/sdk/js/src/gen`                                            | none (frozen)                             | published v1 compatibility client; excluded from lint/prettier |
| `packages/client/src/generated`, `packages/client/src/generated-effect` | `packages/client` generator             | generated; excluded from lint/prettier                        |
| `*.gen.ts` anywhere                                                   | its generator                             | excluded from eslint, oxlint, and prettier                    |
| `**/sst-env.d.ts`, `packages/desktop/src/bindings.ts`                 | SST / desktop tooling                     | excluded from eslint and prettier                             |

Policy: generator → generated output → lint. `eslint.config.js` carries global ignores for these
paths, `.oxlintrc.json` mirrors them, and `.prettierignore` adds the frozen v1 tree, so
`eslint --fix`, `oxlint`, and `prettier` cannot rewrite generator-owned output. Verify with
`bun run lint` (must leave `git status` unchanged) and
`bunx eslint --fix-dry-run <generated path>` (must report "File ignored").

## Prompt ownership

- **V1 runtime assets**: `packages/opencode/src/session/prompt/*.txt` and
  `packages/opencode/src/agent/prompt/*.txt`, consumed by `SystemPrompt`, `SessionReminders`, and
  the agent definitions.
- **V2 runtime assets**: `packages/core/src/session/prompt/*.txt` (provider families plus
  `plan.txt` and `build-switch.txt`), consumed by `packages/core/src/session/system.ts` and
  `packages/core/src/session/reminder.ts`. Core cannot import `packages/opencode`, so these are
  deliberate copies, and the fork keeps the shared ones byte-identical.
- **V2 agent prompts** are inline constants in `packages/core/src/plugin/agent.ts`. `compaction`
  and `summary` match the V1 files; `explore` differs by one bash line and `title` by ASCII arrows.
  Both trees are untouched upstream, so this is upstream-owned phrasing, not migration residue.
- **Fork policy sections** (`## Engineering Execution Loop` in `default.txt`, `## Build Execution`
  in `build-switch.txt`) came from fork commit `7f60b63e11`. They are intentional product policy and
  guarded by `packages/core/test/session-system.test.ts` and
  `packages/opencode/test/session/prompt-policy.test.ts`.

## Type assertions

- 130 `as any` remain in `packages/*/src` outside generated trees. No fork commit added one:
  `git log -S 'as any' ebece6efd7..HEAD -- packages/*/src` is empty.
- Sampled classification: all are boundary assertions over data whose shape an external owner
  defines — legacy provider payload adapters (`packages/console/app/src/routes/zen/util/provider/*`),
  Drizzle generic bridging (`packages/effect-drizzle-sqlite/src/sqlite-core/effect/*`), DOM event
  shims (`packages/ui`, `packages/session-ui`), the Bun SQLite driver's variadic params
  (`packages/core/src/database/sqlite.bun.ts`), and plugin hook duck-typing
  (`packages/opencode/src/plugin/index.ts`).
- This transformation added one boundary assertion: the V2 MCP adapter reads a tool result as
  `CallToolResult` because `McpCatalog.call` already validated it with `CallToolResultSchema` and
  the dynamic tool mode types output as `unknown`. `packages/opencode/test/mcp/capability.test.ts`
  covers the conversion.
- Policy: no `as any` may be added to silence a type error. Decode at trust boundaries; when an
  external system owns the shape and it is already validated, assert at that boundary and test it.

## Remaining gaps

- V2 still resolves only built-in and MCP tool definitions; provider/model filtering of built-in,
  plugin, and structured-output definitions remains open (`packages/core/src/session/runner/llm.ts:72`).
- Configured local/remote instruction sources (URL and config-driven `AGENTS.md`) remain a separate
  V2 design slice; the V2 instruction source covers AGENTS/CLAUDE/CONTEXT discovery.
- `OPENCODE_EXPERIMENTAL_PLAN_MODE` (plan file plus `plan_exit`) stays V1-only until the V2 runtime
  owns a plan artifact; the V2 reminder covers the default plan/build switch.
- `packages/opencode/src/session/prompt/copilot-gpt-5.txt` and `plan-reminder-anthropic.txt` are
  unreferenced in both this fork and upstream. They are upstream-owned assets and stay untouched to
  avoid divergence; add them to a V1 consumer or delete them upstream-first.
